Part A · The Core Theory
CONCEPT 1 · THE CURSE OF HIGH DIMENSIONALITY

Too many features: what goes wrong?

Imagine genetic data: 20,000 genes (features) measured across only 200 patients (rows). When features far outnumber rows, three critical problems emerge:

1. Computational Cost

Massive memory footprint, slower matrix inversions, and lengthy grid search tuning cycles.

2. High Variance (Overfitting)

The model memorizes random noise rather than real signal. Training accuracy hits 100%, but test accuracy collapses.

3. Visualization Barrier

With 30 features, inspecting all pairwise relationships requires 435 separate scatter plots ($30 \times 29 / 2$).

The Packing Analogy

Packing for a weekend trip: you pack only the clothes you will actually wear, not your entire wardrobe.

CONCEPT 2 · TAXONOMY

The Four Families of Feature Selection

1. Filter Methods

Score features using a statistical metric before any model is trained.

Metrics: Pearson correlation, Mutual Information / Information Gain, $\chi^2$ test.
Analogy: Screening CVs on paper before interviewing anyone.

2. Wrapper Methods

Train and evaluate the model repeatedly on different candidate feature subsets.

Strategies: Forward Selection, Backward Elimination, RFE.
Analogy: Holding sports trial days with different squad combinations.

3. Embedded Methods

Feature selection happens inside model training as a natural mathematical penalty.

Examples: LASSO ($L_1$ penalty shrinks coefficients to exactly zero), Random Forest Gini impurity reduction.
Analogy: Learning on the job; weak contributors get phased out.

4. Hybrid Methods

Combine strengths of multiple families (e.g. wrapper search + embedded tree importance).

Examples: Boruta, Genetic Algorithms.
Analogy: Evolutionary tournament testing candidates across generations.

Quick Check: You train a LASSO regression model and discard all features whose learned coefficients are pushed to 0. Which family is this?

CONCEPT 3 · STATISTICAL FEATURE SELECTION

Boruta: Shuffled Noise Sets the Bar

Named after the Slavic forest spirit who lives in a random forest. Boruta answers one crucial question: "Would this feature still look useful if it were pure noise?"

  1. Step 1: Create Shadow Features
    Duplicate every column and randomly shuffle its values. Shuffling preserves the exact empirical distribution (mean, variance, min, max) while completely destroying any relationship with the target $y$.
  2. Step 2: Merge Real and Shadow Features
    Concatenate original features $X$ and shadow features $X_{shadow}$ side-by-side (doubling the column count to $2p$).
  3. Step 3: Train Random Forest & Measure Z-Score
    Train a random forest on the combined dataset. Compute each feature's importance $Z = \text{mean}(imp) / \text{std}(imp)$ across all trees. A feature gets a "hit" if its $Z$-score exceeds the maximum $Z$-score among all shadow features.
  4. Step 4: Binomial Test & Iterate
    Repeat across multiple rounds (default 50–100 trials). Hit counts follow a binomial distribution under the null hypothesis ($p=0.5$). Features statistically above the threshold are Confirmed; features significantly below are Rejected and dropped from subsequent rounds.

Quick Check: Why does Boruta create shadow features by shuffling real values instead of generating fresh Gaussian random numbers?

CONCEPT 4 · BORUTASHAP & SHAPLEY VALUES

BorutaShap: Cooperative Game Theory

BorutaShap keeps the exact same shadow feature logic as original Boruta, but replaces permutation/impurity importance with SHAP values.

Shapley Values (Game Theory)

A team wins a shared bonus. How do you divide the prize fairly? Give each player their average marginal contribution across all possible team orderings.

Applied to ML (SHAP)

Each feature is a "player", the model prediction is the "bonus". SHAP measures the fair share of prediction shift attributed to each feature ($y - \bar{y}$).

Why BorutaShap?

Original Boruta's Gini importance is biased towards high-cardinality features and correlated groups. SHAP values provide consistent, unbiased global feature importance with faster convergence.

CONCEPT 5 · UNSUPERVISED COMPRESSION

Principal Component Analysis (PCA)

PCA does not select features. It creates new orthogonal features (principal components) that are linear combinations of all original features:

PC_k = w_{k,1} X_1 + w_{k,2} X_2 + \dots + w_{k,p} X_p

The Smoothie Analogy

Feature Selection: Picking whole fruits to eat (e.g. keeping bananas and strawberries, throwing out the apple).
PCA: Blending everything into a smoothie. Every glass has a fraction of every fruit; you cannot separate the apple back out.

Mathematical Steps

1. Standardize $X$ (mean=0, std=1)
2. Compute covariance matrix $\Sigma = \frac{1}{n} X^T X$
3. Compute eigenvectors (directions) and eigenvalues (variance)
4. Sort components by descending eigenvalue and project data.

CONCEPT 6 · SENSITIVITY

Why Scaling is Essential for PCA

PCA maximizes variance along orthogonal axes. If one variable has values in the millions (e.g. annual salary) and another has values from 0 to 1 (e.g. credit utilization ratio), the high-magnitude variable will dominate the first principal component regardless of predictive value.

The Digits Experiment (Scaled vs Unscaled)

Even though all 64 pixels are measured on the same 0–16 brightness scale:

  • Unscaled PCA: Center pixels have natural variance up to ~45, while border pixels have variance near 0. Unscaled PCA prioritizes the high-variance center and reaches 95% variance with only 29 components.
  • Scaled PCA: StandardScaler sets every pixel variance to 1.0. This spreads variance equally across all 64 coordinates, requiring 40 components to capture 95% variance.

Why Random Forest Drops on PCA

Decision trees split on single, orthogonal coordinates ($x_j \le c$). Original pixels are sparse and localized. PCA mixes all pixels into dense linear combinations, which forces trees to build awkward staircase approximations.

SUMMARY TABLE

Feature Selection vs Dimension Reduction

Criterion Feature Selection (Boruta) Dimension Reduction (PCA)
Keeps original features? Yes (drops unneeded columns) No (creates new synthetic components)
Interpretability High (original units & variables preserved) Low (each component is a blend of all inputs)
Supervision Supervised (uses labels $y$ to judge importance) Unsupervised (looks only at variance in $X$)
Tree model compatibility Excellent (axis-aligned splits) Poor to moderate (dense continuous rotations)
Linear model compatibility Good Excellent (eliminates multicollinearity)
Primary use case Biomedical, finance, legal transparency High-dimensional compression, 2D/3D visualization
EXAM SIMULATION

Oral Exam Drill: Professor's "Why" Questions

1. "Why can't we just pick the top 10 features by Pearson correlation with the target?"

Answer: Pearson correlation only captures linear relationships and evaluates each feature in isolation (univariate). It misses non-linear interactions and keeps redundant, multicollinear copies of the same information. Boruta evaluates features in non-linear tree ensembles taking multivariate interactions into account.

2. "Why does a Random Forest perform worse on PCA components than on the raw Boruta pixels?"

Answer: Decision trees make axis-aligned cuts ($x_j \le c$). When PCA rotates the feature space into linear combinations of 64 pixels, the clean, localized spatial structure is lost. To partition a diagonal rotated boundary, trees must build complex multi-step staircase splits, increasing variance and error.

3. "In PCA, why does PC1 + PC2 explaining 22% of variance result in poor classification (~51%)?"

Answer: Discarding 78% of the dataset's variance removes the subtle variations needed to distinguish between complex digits like 1, 2, 8, and 9. While PC1 and PC2 separate 0 and 4, 2 dimensions do not provide enough degrees of freedom to linearly separate 10 overlapping handwriting patterns.

4. "Why must PCA and Scaler be fitted only on training folds inside a Pipeline?"

Answer: If you fit `StandardScaler` or `PCA` on the whole dataset before splitting, the learned means, standard deviations, and eigenvector loading vectors leak information from the test/validation sets into training (data leakage). This produces over-optimistic evaluation scores that collapse in production.
